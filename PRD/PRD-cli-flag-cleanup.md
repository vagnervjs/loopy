# PRD: CLI Flag Renames and Legacy Cleanup

## Problem Statement
The CLI still exposes legacy flags and docs that no longer match the desired UX, causing confusion and inconsistent usage.

## Goals
- Align the CLI with the new flag names and plan terminology.
- Remove deprecated/legacy options and commands to simplify UX.
- Update documentation so it reflects the current CLI surface.

## Non-Goals
- Introduce new features unrelated to flag/command renaming or cleanup.

## Users & Context
- Primary user: developers using the Loopy CLI locally.
- Secondary user(s): contributors maintaining docs and guides.
- Environment: local CLI usage on macOS/Linux/Windows.

## Scope
- In scope:
- Use `--plan-file` for the plan doc path and align terminology around “Plan doc”.
  - Use `--agent` for the agent command override.
  - Remove legacy/deprecated flags and commands.
  - Move autogenerated `PROMPT.md` into `.loopy/`.
  - Move `LOOPY_PLAN.md` into `.loopy/` (user-created or autogenerated).
  - Refresh `/examples` to match new flags and file locations.
  - Update documentation to reflect the new CLI surface.
- Out of scope:
  - Changing CLI behavior beyond name/UX alignment.
  - Refactoring unrelated runtime logic or prompts.

## Requirements
### Functional
- [F1] CLI accepts `--prd` as the PRD seed flag.
- [F2] CLI help text and docs refer to "Plan doc" (not "Task doc").
- [F3] CLI accepts `--agent` as the agent command override flag.
- [F4] Legacy/deprecated flags and commands are removed from parsing and help output.
- [F5] Autogenerated prompts are written to `.loopy/PROMPT.md`.
- [F6] Plan files live at `.loopy/LOOPY_PLAN.md` by default, regardless of origin.
- [F7] Example files are regenerated to match new flags and file paths.
- [F8] Documentation updates cover all renamed/removed options and new paths.
- [F9] If `agent_command` is missing, prompt the user to define it before running.
- [F10] If `test_command` is missing, prompt the user to define it before running.
- [F11] If `git.branch` is missing, auto-generate one using the `loopy/` prefix.

### Non-Functional
- [N1] Compatibility: changes should be explicit; no silent fallback to legacy flags.
- [N2] UX clarity: help output must be consistent and concise.
- [N3] File layout: generated files should stay inside `.loopy/` unless explicitly overridden.

## User Stories (MVP)
- As a user, I want to use `--prd` so it matches PRD terminology.
- As a user, I want to use `--agent` so that the CLI flag is concise and clear.
- As a user, I want help/docs to match the actual CLI options so I can avoid errors.
- As a user, I want generated prompts and plans stored under `.loopy/` so the repo root stays clean.
- As a user, I want the examples to mirror the current CLI and file layout.

## Success Metrics
- CLI help and docs contain zero references to legacy flag names.
- All deprecated flags/commands are removed from parsing, help, and docs.
- Autogenerated prompt and plan files live under `.loopy/` by default.
- `/examples` content matches the updated CLI surface and file locations.

## Risks & Mitigations
- Risk: users rely on old flags → Mitigation: explicit release notes or changelog entry.

## Open Questions
- Are there any legacy options that must remain for a deprecation period?

## Assumptions
- The Plan doc replaces the Task doc across the CLI and documentation.
- `.loopy/` is the canonical home for generated plan and prompt files.
